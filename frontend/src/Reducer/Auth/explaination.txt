## Step 2: `store.getState` Asal Mein Kya Hai

store.getState() ka matlab hai:

“Redux store ke andar jo current data hai wo mujhe de do”

Example:

store.getState()

ye return karega:

{
  auth: {
    loggedInUser: null,
    loading: false
  }
}

Ab is returned object ki ek shape hoti hai:

{
  auth: {
    loggedInUser: null,
    loading: false
  }
}

TypeScript isi shape ko save karta hai:

export type RootState = ReturnType<typeof store.getState>

Simple words mein:

RootState = Redux store ka structure/type

Yani TypeScript ko ab pata hai:

state.auth.loggedInUser
state.auth.loading

exist karte hain.

Is se:

autocomplete milta hai ✅
typo errors pakar mein aate hain ✅
safety milti hai ✅

## Step 3: RootState Kis Problem Ko Solve Karta Hai

```typescript
// SOCHO agar RootState NA ho
// Tum selector likhte ho:

export const selectLoggedInUser = (state) => state.auth.loggedInUser
//                                 ^^^^^
//                      TypeScript poochta hai:
//                      "state kya hai?"
//                      "iske andar kya hai?"
//                      ".auth exist karta hai?"
//                      ".auth.loggedInUser exist karta hai?"
//                      TypeScript ko kuch nahi pata
//                      Is liye wo help nahi kar sakta

// Tum typo kar dete ho:
state.auht.loggedInUser   // typo: "auth" ki jagah "auht"
// TypeScript is error ko pakar nahi sakta
// App runtime pe crash ho jati hai
// Tum 2 ghante typo dhundte rehte ho
```

```typescript
// AB RootState KE SATH:

export const selectLoggedInUser = (state: RootState) => state.auth.loggedInUser
//                                         ^^^^^^^^^
//                       Ab TypeScript ko pata hai:
//                       state = { auth: { loggedInUser, loading } }

// Tum typo karte ho:
state.auht.loggedInUser
//    ^^^^
// ERROR: "auht RootState mein exist nahi karta"
// TypeScript foran red underline dikha deta hai
// Tum turant fix kar lete ho
// App crash nahi hoti
```

## Step 4: ACTUAL Flow — Data Ko Follow Karo

```text
Ab dekhte hain EXACTLY kya hota hai
jab component store se loggedInUser read karta hai
```

### Part A: authReducer.ts Run Hoti Hai

```typescript
// Ye file run hoti hai aur cheezein create karti hai

// 1. authSlice create hoti hai
const authSlice = createSlice({
  name: "auth",
  initialState: { loggedInUser: null, loading: false },
  reducers: {}
})

// 2. authReducer extract aur export hota hai
export const authReducer = authSlice.reducer
// authReducer ab ek FUNCTION hai
// Ye { loggedInUser, loading } ko manage karna janta hai

// 3. Selectors create aur export hote hain
export const selectLoggedInUser = (state: RootState) => state.auth.loggedInUser
export const selectLoading = (state: RootState) => state.auth.loading

// Ye sirf FUNCTIONS hain
// Jab tak koi CALL na kare ye kuch nahi karte
// Ye wait kar rahe hote hain
```

---

### Part B: store.ts Run Hoti Hai

```typescript
// store.ts authReducer ko import karti hai
import { authReducer } from "../reducer/authReducer"

// configureStore run hota hai
// Ye authReducer ko bolta hai:
// "Tum AUTH section manage karoge"

const store = configureStore({
  reducer: {
    auth: authReducer
  }
})

// AB store memory mein exist karta hai:
// store.getState() return karta hai:
{
  auth: {
    loggedInUser: null,
    loading: false
  }
}

// RootState describe hota hai (create nahi hota, sirf describe)
export type RootState = ReturnType<typeof store.getState>

// TypeScript ko ab pata hai:
RootState = {
  auth: {
    loggedInUser: null | User,
    loading: boolean
  }
}

// AppDispatch bhi describe hota hai
export type AppDispatch = typeof store.dispatch

// TypeScript ko dispatch function ka type pata chal jata hai
```

---

### Part C: main.tsx Run Hoti Hai

```typescript
// Provider poori app ko wrap karta hai
// Is se store har component ko available ho jata hai

<Provider store={store}>
  <App />
</Provider>

// Provider store ko React context mein daal deta hai
// Context = data share karne ka tareeqa bina prop drilling ke
// Ab har component store access kar sakta hai
```

### Part D: Component Run Hota Hai (SignIn.tsx)

```typescript
const SignIn = () => {

  // useAppSelector call hota hai
  const loggedInUser = useAppSelector(selectLoggedInUser)

  // EXACTLY kya hota hai:

  // Step 1:
  // useAppSelector current store state leta hai

  // currentState = store.getState()

  // currentState =
  // { auth: { loggedInUser: null, loading: false } }

  // Step 2:
  // useAppSelector selector ko call karta hai

  // selectLoggedInUser(currentState)

  // Step 3:
  // selectLoggedInUser run hota hai

  // (state: RootState) => state.auth.loggedInUser

  // state = { auth: { loggedInUser: null, loading: false } }

  // state.auth = { loggedInUser: null, loading: false }

  // state.auth.loggedInUser = null

  // Step 4:
  // null return hota hai

  // loggedInUser = null

  // Step 5:
  // Component render hota hai

  // loggedInUser null hai
  // User login nahi hai
  // Login form show karo
}
```

## Step 6: Jab User Login Karta Hai

```text
User form fill karta hai aur Sign In pe click karta hai
        │

dispatch(setUser({ email: "ali@gmail.com", ... }))
        │

        │

        │   type: "auth/setUser",
        │   payload: {
        │      email: "ali@gmail.com",
        │      token: "jwt..."
        │   }
        │ }
        │
        ▼
authReducer action receive karta hai

authReducer state update karta hai:

{
  loggedInUser: {
    email: "ali@gmail.com",
    token: "jwt..."
  },
  loading: false
}

        │
        ▼
Store ke paas nayi state aa jati hai:

{
  auth: {
    loggedInUser: {
      email: "ali@gmail.com"
    },
    loading: false
  }
}

        │
        │ Redux sab components ko bolta hai:
        │ "State change ho gayi!"
        │
        ▼
useAppSelector dobara selector run karta hai

return karta hai:
{
  email: "ali@gmail.com",
  token: "jwt..."
}

        │
        ▼

```

## Sabse Simple Yaad Rakhne Wala Version

```text
RootState jawab deta hai:
"Mera store dikhta kaisa hai?"
────────────────────────────────

Ye store ki shape ka description hota hai
Selectors ko pata chalta hai kya access kar sakte hain

state.auth exist karta hai kyun ke:
auth: authReducer store mein diya gaya hai

state.auth.loggedInUser exist karta hai
kyun ke AuthState mein loggedInUser hai


AppDispatch jawab deta hai:
"Main store ko kya bhej sakta hoon?"
──────────────────────────────────

Ye dispatch function ka type hota hai
TypeScript check karta hai actions valid hain ya nahi


authReducer jawab deta hai:
"Auth state kaise change hogi?"
─────────────────────────────

Ye actual function hota hai jo state update karta hai
dispatch jab action bhejta hai
to authReducer decide karta hai kya karna hai


selectLoggedInUser jawab deta hai:
"Mujhe store se user de do"
──────────────────────────

Ye function poora store receive karta hai
Aur sirf required piece return karta hai


Poora system:
store data rakhta hai
dispatch data change karta hai
selectors data read karte hain
RootState aur AppDispatch TypeScript safety dete hain
```
